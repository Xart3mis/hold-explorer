# M1c-export: Export, Reports, Sorting, and Selected Rows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user sorts any table by any of its columns, selects several rows at once, and takes what a data screen shows out of the app: as an Excel workbook of this view or of every screen at once, as CSV, on the clipboard, as a chart in PNG or SVG, or as a PDF status report, with the columns and rows they choose, and a notice that opens the file or shows it in its folder.

**Architecture:** A new crate, `crates/export` (`hx-export`), turns what the core answers into files: a table model (`Sheet`) shared by Excel, CSV, and the clipboard text; charts drawn as SVG and rasterized to PNG; a PDF report whose pages are SVG drawn into a PDF with embedded fonts. The desktop crate gathers the content under the state lock, releases it, writes the file atomically off the interface thread, and reports progress on a channel, as import does. The interface builds the request (screen, columns, rows, filters, and every text a file contains, from its catalog) and shows the result. Rust sorts the paged tables; the interface sorts only tables whose rows it holds whole.

**Tech Stack:** As M1c-2, plus in `hx-export`: `rust_xlsxwriter` (workspace, 0.99), `krilla` 0.8 and `krilla-svg` 0.8 (PDF), `resvg` pinned to `=0.47.0` so it shares `usvg` 0.47 with `krilla-svg`, `ttf-parser` 0.25 (text widths, already in the tree through `fontdb`); in `hx-desktop`: `arboard` 3 with `wayland-data-control` (clipboard text and image). Public Sans and Reddit Mono as static TTF instances under the SIL Open Font License, embedded in the binary.

## How this plan is written

As M1c-1 and M1c-2: each task gives its files, the exact interface later tasks rely on, the rules, and the test cases; not the implementation. Test cases are the requirements and are written failing first. Where a library behaves otherwise than this plan assumes, the implementer reads the installed source, adapts, and reports it. Every task runs the checks of CI that its change touches (`cargo fmt --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm bindings` with no diff) and reports their output.

## Decisions this plan rests on

1. **Scope** (owner, 2026-10-17 and 2026-10-18): spec 10.4 to 10.6, and four extras: every screen at once in one workbook; choosing columns and rows before export, remembered per screen; charts as PNG or SVG to a file or the clipboard; the PDF status report. Excel is wanted by name. Added on 2026-10-18: every column of every table sortable where possible.
2. **"Full workbook" and "every screen at once" are one action**, "Full workbook": About, Summary, a breakdown sheet for each dimension the snapshot has, two cross-tabs (holds and lines, discipline by hold type), Lines, Holds, and Solve order, all under the current filters. Spec 10.4's full workbook already lists these parts.
3. **Several rows are selected as in Excel** (owner, 2026-10-18): a plain click selects one row and opens its panel, as today; Ctrl+click adds or removes a row; Shift+click selects the range from the last pressed row; Shift+Up and Shift+Down extend; Ctrl+A selects every loaded row; Escape clears the selection and closes the panel. The panel shows the last row pressed. The selection is held by the page, never in the address, and is cleared when the rows are read again for another result (filters, sort, mode).
4. **The export menu** (owner, 2026-10-18): an Export menu button in the page header of Overview, Breakdown, Lines, and Blockers. Its items run at once with the remembered columns and rows of the screen: Excel (this view) on `Ctrl+E`, Full workbook, CSV; Copy table, Copy selected rows, Copy line IDs; chart items (Save as PNG, Save as SVG, Copy); Status report (PDF); and a last item, "Columns and rows", that opens a panel to change them. Items that do not apply to the screen are left out, not shown disabled (Overview has no rows to select; Lines has no chart).
5. **The PDF status report is A4 portrait** (owner, 2026-10-18). Its M1 content: header (workspace, snapshot date, time made, active filters), the stat tiles without deltas, bars by discipline, hold type, and role, top blockers, the head of the solve order with its curve, the oldest open holds, and the stale holds. Deltas, the trend, and changes since the previous snapshot arrive with M2 and are not drawn empty.
6. **Files are drawn in the light theme**, whatever the app's theme: they are printed and pasted into documents. Colors come from `DESIGN.md` tokens through a fixture that the token checker verifies.
7. **Every text in a file comes from the interface's catalog.** The request carries `ExportText`: the labels by key and the twelve short month names, which the interface fills from `en.json` and `Intl`. A Rust test and an interface test read one fixture of the keys, so neither side can lack one. Rust writes numbers and dates; the interface writes words.
8. **Whole and paged tables.** For Lines and Holds the request names the sort, and Rust orders the rows as the command does. For tables the interface holds whole (Breakdown groups, Blockers steps), the request carries the row keys in the order on screen, so the file has the order the user sees.
9. **The window gains one permission, `dialog:allow-save`.** "Open file" after saving is a command that opens only a path the app wrote in this session, through the opener plugin's Rust API, not through a new window permission. Spec 14 is updated to name both.
10. **A file is written whole or not at all:** into a temporary file in the target folder, then renamed over the target. A target that another program holds open fails with the kind `FileInUse` and the message "close the file or choose another name" (spec 14).
11. **Chosen columns and rows are remembered per screen on this computer** (browser storage, read and written inside `try`), as the sidebar is; they are not in the settings file.
12. **Tables left unsortable, with the reason:** the import mapping preview (the first rows of the file, shown in file order so that a column can be recognized) and the skipped rows of the import review (a sample of the skipped rows; sorting a sample misleads). The lists in the detail panel are lists, not tables, and keep their order.

## Global Constraints

Every constraint of the M1c-2 plan holds, unchanged:

- Real project files never enter the repository; tests build inputs with `hx-synth` or small text files in temporary directories.
- `hx-core` and `hx-store` do not depend on Tauri; `ts-rs` only behind the `ts` feature. `hx-export` follows the same rule.

- A screen reads snapshot data only through `useSnapshotQuery` or `useSnapshotPages`, and changes the view only through `workspaceAction()`. A table without a selection handler is read-only. The pending rule holds.
- Rust: edition 2021, toolchain 1.97.0; `hx-desktop` `rust-version = "1.90"`, `hx-export` `"1.92"` (what `krilla` needs), others `1.88`; `#![forbid(unsafe_code)]`; no `unwrap()`/`expect()` outside tests except on values that cannot fail, with the reason; no `#[allow]`; every public item documented.

- Every user-facing string is in `ui/src/locales/en.json`, including every text written into a file; glossary terms; errors say what happened, why, and how to fix it.
- Spec 13.1 and 13.2 bind every screen, chart, and file: all states; skeletons on first load; dimmed previous render on refetch; empty states name the next action; motion 150 to 250 ms on state changes only, none under reduced motion; nothing by hover alone; WCAG AA in both themes; banned patterns; charts with a tooltip, keyboard focus that shows what hover shows, and a table view; color follows the entity; no two value axes; status colors only for real states, with icon and label.

- Never relax a supply-chain or security policy. The only change to `src-tauri/capabilities/default.json` is `dialog:allow-save`. The content security policy is unchanged. The app makes no network request.
- Parity tests and `tools/parity/reference.mjs` unchanged; existing performance limits stay; `query::*` functions keep their results for existing calls; existing `LineSort` and `HoldSort` variants keep their order and meaning.
- Keyboard reaches everything; focus always visible.
- Conventional Commits; no em dashes in documents, interface text, or file text.

New for this plan:

- Files render identically on Windows and Linux: no system font is read (`fontdb` holds only the embedded faces; `resvg` and `usvg` without `system-fonts`), no time zone or locale of the machine enters a file except the local time the About sheet and the report header state.
- A file name is `HoldExplorer_<workspace>_<view>_<snapshot date>.<extension>` (spec 10.6), the snapshot date as `YYYY-MM-DD`, the workspace name with every character a file system refuses (`\ / : * ? " < > |` and control characters) replaced by `-`.
- Export never holds the state lock while it writes a file.
- Binary under 25 MB (spec 17); the release binary was 12.2 MiB before this plan, and a prototype of the PDF and image crates with the fonts measured about 4 MiB.

### Task 1: Every column of Lines and of the hold rows sorts

**Files:** `crates/core/src/query.rs` (tests in the same file); `ui/src/features/lines/{sorts.ts, sorts.test.ts, lineColumns.tsx, holdColumns.tsx, *.test.tsx}`; `ui/src/bindings/`; `crates/cli/tests/perf.rs` if a new sort is slower than the 100 ms filter budget at 10,000 rows (it must not be).

**Interface:**

```rust
pub enum LineSort {
    // existing variants unchanged, in their order, then:
    /// Most distinct hold types first.
    HoldTypes,
    /// Lines whose sizes differ first; ties end in line ID order.
    SizeMismatch,
}
pub enum HoldSort {
    // existing variants unchanged, in their order, then:
    /// Remark ascending without regard to case; an empty remark comes last.
    Remark,
    /// Blocker type ascending without regard to case.
    BlockerType,
    /// Role ascending; holds with the blank spelling `—` come last.
    Role,
    /// Creation date, oldest first; holds without one come last.
    Created,
    /// Release date, earliest first; holds without one come last.
    ReleaseDate,
    /// Open holds first, then released ones; ties stay in file order.
    Status,
}
```

`LINE_SORTS` gains `{ column: "holdTypes", sort: "HoldTypes", natural: "descending" }` and `{ column: "sizes", sort: "SizeMismatch", natural: "descending" }`; `HOLD_SORTS` gains `remark` (`Remark`, ascending), `blockerType` (`BlockerType`, ascending), `role` (`Role`, ascending), `created` (`Created`, ascending), `releasedOn` (`ReleaseDate`, ascending), `status` (`Status`, ascending).

**Rules:** each new sort follows `order_by`: rows without the value last in both directions, `reverse` flips only the comparison of keys, ties as the enum says. After this task every column of both tables has `allowsSorting`, and a test says so for each column id.

**Tests (failing first):** for each new variant, on a hand-built dataset: the order, the rows without a value last, the order reversed with those rows still last, ties. Interface: every column of `lineColumns` and `holdColumns` (all three statuses) is sortable; pressing each header sends the query `lineSortOf` and `holdSortOf` give, and a second press reverses it; the marked header follows the address.

**Commit:** `feat: sort Lines and hold rows by every column`

### Task 2: Tables held whole sort by every column

**Files:** new `ui/src/components/useTableSort.ts` with tests; `ui/src/components/DataTable/DataTable.tsx` (column `sortValue`), `ui/src/components/charts/ChartTable.tsx`; `ui/src/features/breakdown/{ListMode.tsx, address.ts}`, `ui/src/features/blockers/{BlockersPage.tsx, columns.tsx, address.ts}`, `ui/src/features/overview/GroupSection.tsx`, `ui/src/features/welcome/WelcomePage.tsx`, the charts that give `ChartTable` its rows (`Heatmap`, `LineChart`, the Overview's table views); tests; `DESIGN.md` (Table: which tables sort, and the two that do not, with the reasons of decision 12).

**Interface:**

```ts
// A column of a table whose rows the screen holds whole may say what it sorts by.
interface ColumnBase<Item> {
  // ...as today, plus:
  /** The value the rows are ordered by when this header is pressed; `null` for a row without
   * one, which stays last in both directions. Giving it makes the header sortable. */
  sortValue?: (item: Item) => string | number | null;
  /** The direction of a first press: `descending` for counts and ages, `ascending` for text. */
  sortFirst?: "ascending" | "descending";
}

/** Sorts rows held whole by the column a header asks for. Text compares with
 * `Intl.Collator` (base sensitivity, numeric); numbers compare as numbers; ties keep the order
 * the rows came in. `initial` is the sort the rows are in as they come (none: unmarked). */
export function useTableSort<Item>(
  rows: readonly Item[],
  columns: readonly { id: string; sortValue?: ...; sortFirst?: ... }[],
  sort: DataTableSort | undefined,
): readonly Item[];
/** The sort a pressed header asks for: its first direction, or the other one when it is the
 * sorted header. */
export function nextSort(columns, current: DataTableSort | undefined, column: string): DataTableSort;
```

`ChartTableRow` gains `values: readonly (string | number | null)[]`, one per column, the raw values its cells format; every `ChartTable` column sorts by it. A row marked `isFolded` (the "All others" row of the heatmap) stays last in both directions.

**What sorts, and where the sort is kept:** Breakdown groups (label ascending, share and holds descending by holds, lines descending): in the address as `sort=<column>&dir=<asc|desc>`, dropped when the dimension changes; the default, unmarked, is the command's order (most holds first). Blockers steps (step ascending, blocker, type, discipline ascending, holds, lines freed, lines freed so far descending): in the address the same way; the curve keeps the order of the steps; a selected step past the rows handed to the table is handed over with the rows before it in the table's order. The table views of every chart, the Overview's group tables, and the Welcome workspace list: in the component's state, not kept.

**Rules:** the sort of a table held whole is presentation: it never sends a request. Load-more of the Blockers table hands rows in the sorted order. The child rows of an expanded group keep the order of `group_detail`.

**Tests:** `useTableSort`: text with the collator (case, accents, numbers in text), numbers, `null` last both ways, stable ties, the folded row last. Each table: every column sortable; pressing a header reorders the rows and marks it; a second press reverses; Breakdown and Blockers keep the sort in the address and drop it on a dimension change; Blockers selection of a step beyond the handed rows still reveals it in the sorted table; `axe`.

**Commit:** `feat(ui): sort every table the screen holds whole by any column`

### Task 5: The export crate: sheets, text formats, and safe writes

**Files:** new `crates/export/{Cargo.toml, palette.json, src/lib.rs, src/sheet.rs, src/text.rs, src/file.rs}`; root `Cargo.toml` (member, workspace dependencies); `ui/src/api/file-text-keys.json`; `src-tauri/Cargo.toml` (dependency, `ts` feature); a test in `tools/design/check-tokens.test.mjs` that every entry of `palette.json` equals the light-theme value the checker prints for that token.

**Interface:**

```rust
/// What a cell of a sheet holds. Dates are calendar days; numbers keep their kind.
pub enum Cell { Text(String), Count(usize), Days(i64), Size(f64), Date(NaiveDate), Flag(bool), Empty }
/// What a column holds; it decides formats in Excel and nothing in text.
pub enum ColumnKind { Text, Identifier, Count, Days, Size, Date, Flag, LongText }
pub struct Column { pub id: String, pub header: String, pub kind: ColumnKind }
/// One table of a file: a sheet of a workbook, a CSV file, or the text on the clipboard.
pub struct Sheet { pub name: String, pub columns: Vec<Column>, pub rows: Vec<Vec<Cell>> }

/// Every word a file contains, from the interface's catalog.
#[derive(Deserialize, ts)] pub struct ExportText {
    /// By key; the keys are those of `ui/src/api/file-text-keys.json`.
    pub labels: BTreeMap<String, String>,
    /// The twelve short month names, January first, as the interface writes dates.
    pub months: Vec<String>,
}
impl ExportText {
    /// The label of `key`; `Err(ExportError::Text)` naming the key when it is missing.
    pub fn get(&self, key: &str) -> Result<&str, ExportError>;
    /// `30 Sept 2026`, as the interface's `formatDate` writes it.
    pub fn date(&self, day: NaiveDate) -> String;
}

/// CSV in UTF-8 with a byte-order mark, comma-separated, CRLF line ends, fields quoted when they
/// hold a comma, a quote, or a line break. Dates `YYYY-MM-DD`; numbers as plain digits.
pub fn csv(sheet: &Sheet) -> Vec<u8>;
/// Tab-separated text for the clipboard: a header row, then the rows; a tab or line break
/// inside a value becomes a space. Dates as `ExportText::date` writes them.
pub fn tab_separated(sheet: &Sheet, text: &ExportText) -> String;
/// One line ID per line, each once, in the order given.
pub fn line_ids(ids: &[String]) -> String;

/// Writes `bytes` to `path` whole or not at all: a temporary file in the same folder, then
/// renamed over `path`.
pub fn write_file(path: &Path, bytes: &[u8]) -> Result<(), ExportError>;

#[derive(Debug, thiserror::Error, Serialize)] #[serde(tag = "kind")]
pub enum ExportError {
    /// Another program holds the file open, or it is read-only.
    FileInUse { file: String },
    /// The folder does not exist or cannot be written.
    Folder { folder: String, reason: String },
    /// Any other failure to write, with the system's reason.
    Write { file: String, reason: String },
    /// A label the request lacks: a fault of the application.
    Text { key: String },
}
```

**Rules:** messages say what happened, why, and how to fix it; `FileInUse`: "Hold Explorer could not save <file>: another program has it open, or it is read-only. Close it in that program, or choose another name, and save again." A sharing violation on Windows (OS errors 32 and 33) and permission denied on an existing file map to `FileInUse`; a missing folder to `Folder`. The temporary file is removed on every failure. `palette.json` holds, by token name, the light-theme hex value of each color the files use (ink, muted ink, hairline, surface, the neutral bar, the blue ramp steps, the age-band ramp), and nothing else.

**Tests:** CSV: BOM, quoting, CRLF, a remark with a line break, a date, an empty cell, a non-ASCII name; reopened with the `csv` crate equals the sheet. Tab-separated: header, tabs and line breaks inside values. `line_ids`: duplicates removed, order kept. `write_file`: writes; replaces an existing file; a missing folder gives `Folder` and writes nothing; a failed write leaves the earlier file as it was and no temporary file; on Windows only (`#[cfg(windows)]`), a file held open with sharing denied gives `FileInUse`. `ExportText::get` of a missing key; `date` for each month. The key fixture: a test lists every key the crate asks for (one `const` list) and compares it with `file-text-keys.json`; the interface's test in Task 11 compares the same file with the catalog.

**Commit:** `feat(export): sheets, CSV, clipboard text, and safe writes`

### Task 6: The sheets of every screen

**Interface:**

```rust
/// Which screen a file is made from, as the interface shows it.
#[derive(Deserialize, ts)] #[serde(tag = "kind")]
pub enum Screen {
    Overview,
    Lines { query: LineQuery },
    Holds { sort: HoldSort, reverse: bool },
    Breakdown { dim: Dim },
    Matrix { rows: Dim, cols: Dim },
    Blockers,
}
/// Which rows of the screen go into the file.
#[derive(Deserialize, ts)] #[serde(tag = "kind")]
pub enum RowScope {
    /// Every row the filters keep, in the screen's order.
    All,
    /// The first `count` rows in the screen's order: the rows the table has loaded.
    First { count: usize },
    /// These rows, in this order: line IDs, hold positions as text, group keys, or step keys.
    Keys { keys: Vec<String> },
}
/// The request of every export.
#[derive(Deserialize, ts)] pub struct ExportRequest {
    pub screen: Screen,
    /// Column ids to write, in table order; empty writes every column the snapshot has.
    pub columns: Vec<String>,
    pub rows: RowScope,
    pub spec: FilterSpec,
    pub text: ExportText,
    /// The active filters as the filter bar writes them, one per entry, for About and the report.
    pub filters: Vec<String>,
}
/// The sheets of `screen` under `spec` (already made applicable by the caller), with the
/// columns and rows asked for. `plan` is the solve plan of the open kept holds, for Blockers.
```
